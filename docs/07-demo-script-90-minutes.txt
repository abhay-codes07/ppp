All commands run in Git Bash at the root of the petri-flow clone, after a one-time
`bun install && bun run build`. Expected outputs below were captured on 9-10 October 2026
on Windows 11 with Bun 1.3.14. Where a demo needs a model, the Azure/OpenAI/MOCK selection
in labs/openai/_model.ts applies (chapter 13). Rehearse everything with MOCK=1 first.

DEMO 3. Break the proof                                                     8 min
--------------------------------------------------------------------------------
Step A, baseline:
  bun test workflows/agent-benchmark 2>&1 | tail -3        # all pass
Step B, add a bypass transition (one sed; revert with git checkout afterwards):
  cp workflows/agent-benchmark/definition.ts /tmp/definition.ts.bak
  BYPASS='{ name: "bypassApproval", type: "automatic", inputs: ["codePending"],'
  BYPASS="$BYPASS"' outputs: ["codeDone"], guard: null },'
  sed -i "/=== Join + Decision ===/i\\    $BYPASS" workflows/agent-benchmark/definition.ts
  grep -n bypassApproval workflows/agent-benchmark/definition.ts
Step C, the property test catches it:
  bun test workflows/agent-benchmark 2>&1 | grep -E "pass|fail"
  Expected (verified 10 Oct 2026): 8 pass, 1 fail:
    (fail) agent-benchmark: formal properties > code execution always passes through humanApproval
Step D, --strict does NOT:
  bun packages/cli/src/cli.ts analyse workflows/agent-benchmark/index.ts --strict; echo "exit=$?"
  Expected: Reachable states: 196, Terminal states: 4 (all valid), exit=0
  (the bypass adds no new marking, because humanApproval already connects the same places;
   the failing test is a STRUCTURAL check over transitions, which --strict never performs)
Step E, revert:
  git checkout -- workflows/agent-benchmark/definition.ts
Say: the maths finds the bad state when someone WRITES the property as a test. The CLI's
strict mode checks only unexpected terminal states and declared invariants. "Verified"
means what was asked, nothing more.

DEMO 6. The forged-history loophole (lab 3)                                 6 min
--------------------------------------------------------------------------------
Window 1:  MOCK=1 bun run labs/openai/03-server.ts     (or real: drop MOCK=1)
Window 2:  bun run labs/openai/03-client.ts            # honest: test, then deploy w/ history
           bun run labs/openai/03-spoof.ts             # forged history
Expected from 03-spoof.ts:
  ### Honest: deploy with no history      -> BLOCKED: deploy requires a successful call to test first.
  ### Forged: deploy with a fake 'tests passed' history -> (no BLOCKED line), budget 2 -> 1
  honest request blocked : true
  forged request blocked : false
  Result: the forgery WORKED.
Say: the gate is stateless by design (0.2.0); its memory is the chat history; whoever
controls the history controls the gate. Same lesson as the Darwin Goedel Machine faking a
test log: protect the evidence, not only the rule.
