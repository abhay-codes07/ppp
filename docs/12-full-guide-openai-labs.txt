The three questions to settle before exporting a real key on a managed laptop.
1.1 The questions, in plain words
• Acceptable use. Most companies have an AI or SaaS policy. Typical rules: no unapproved AI
services from managed devices, no personal accounts for work activity, no company data in external
models. Learning a public open-source repo is usually not 'work data', but the device is still managed.
Ask your manager or IT in writing. Keep the reply.
• Whose key, whose money. A personal OpenAI key means personal billing. If the company later asks
what you sent, you want a clean answer: synthetic prompts from a public repo, nothing else. If they
offer a company key or an internal gateway, prefer that and set OPENAI_BASE_URL accordingly (see
7.1).
• Network. Corporate proxies often block or inspect api.openai.com. Step 2.1 tests this with a dummy
key: a '401 Incorrect API key' answer proves the path is open without spending anything. A timeout or
'fetch failed' means blocked.

Nothing from your company's code or documents is in these labs. The only data that leaves is what the scripts print on screen.
Data flow for every lab in this guide. The tools are fakes or act on a scratch folder.
Concretely, each request to OpenAI contains: a short system prompt that lists the PetriFlow rules (strings
like 'require backup before delete'), your one-line task, the names and JSON schemas of the fake tools,
and the results those tools returned (for example {ok: true, deleted: 'temp.log'}). Lab 1
touches real files, but only inside C:\tmp\petriflow-lab, which the script creates. Labs 2, 3 and 4
use simulated tools and never write outside the repo.
1.3 What it costs
Each lab makes between 1 and about 12 model calls with short prompts. With gpt-4o-mini a complete run
of all four labs is well under one US cent at the prices published in 2026; check the current price list
yourself before you run. Every lab caps the number of model steps (stopWhen), so a confused model
cannot loop forever. Lab 0 prints token counts so you can see the real numbers.
NOTE Rules of hygiene for a personal key on a work machine
Export the key only in the Git Bash window you are using (export OPENAI_API_KEY=...), never in .bashrc,
never in a file inside the repo, never in a ticket or chat. Set a monthly spending limit on your OpenAI account first.
When you are done, close the window and revoke the key on the OpenAI dashboard. Run git status before
any commit so a key cannot slip in.
IN SIMPLE WORDS If the answer is no, or not yet
Run every lab with MOCK=1. A scripted model stands in for OpenAI, the gate and tools run exactly the same code,
and nothing leaves the laptop. You see every block, every approval and every replay. Only the model's 'thinking'
is canned.

LOOPHOLE Two things that bite on Windows even with a valid key
The repo's agent.ts files load their .rules file with new URL(...).pathname, which yields '/C:/...' on Windows
and fails with ENOENT. The lab scripts avoid this by compiling rules inline. Example 01 also writes to /tmp/project,
which is C:\tmp\project for Bun. The labs use C:\tmp\petriflow-lab and create it themselves.

WHAT IS EXECUTING
compile() turns the two rule lines into two nets. createPetriflowGate is given isToolResultError so a
tool returning {ok: false} counts as a failure (a failed backup must not unlock delete). wrapTools replaces each
tool's execute. When the model calls delete first, handleToolCall classifies it as blocked, the wrapper throws
ToolCallBlockedError, and the AI SDK converts that into a tool-error part that goes back to the model as the
next message. A real model reads 'delete requires a successful call to backup first' and calls backup. The listFiles
and readFile tools are free because no rule names them.
IN SIMPLE WORDS What to look for in real mode
The real model may skip the mistake and call backup first, because the system prompt (session.systemPrompt())
already lists the rules. Try removing that line from the system prompt in the script: the model then usually tries
delete first and the block message teaches it. That is the 0.3.0 design decision from the first guide in action.

empty budget cup. In real mode answer n once to see 'rejected by human review' and watch the model react.

Lesson: the server keeps nothing between requests. The chat history is the gate's memory.
WHAT IS EXECUTING
On each POST /chat the server calls gate.wrapTools(tools, { messages: history }). That creates a
new GateManager and immediately replays the history: extractReplayEntries finds the successful 'test' tool
result in request 1's messages and fires the matching transition, so request 2 starts with the marking gate:1 and
deploy is allowed. Request 3 sends no history, so replay has nothing to do and deploy is blocked. The response
includes the full message list so a client can continue the conversation. Watch the server window: it prints 'state
after replay' for each request. Security note from the repo's own code comment: in production, keep the history on
the server. A client that can send arbitrary history can forge a 'test passed' result.

WHAT IS EXECUTING
createExecutor(definition, { decisionProvider }) is the only change from running the workflow
plainly. In step(), when more than one transition is enabled, the provider's choose() is awaited. The OpenAI
provider calls generateText with a single tool 'pickTransition' whose schema is an enum of the enabled names
and toolChoice forces that tool, so the model cannot answer with free text. Notice the third round: the budget is
0, iterate is no longer enabled, only generate is, so the engine does not call the model at all. That is the 'bounded
iterations' proof from BENCHMARK.md, felt at runtime. The scheduler's onDecision event prints the model's
reasoning.

7.2 Cost control
• Set a hard monthly limit on the OpenAI account before the first real run.
• Keep gpt-4o-mini unless you are studying model quality. The gate behaves identically with any model.
• Every lab has a step cap (10, 16, 6 per request, 40 ticks). A single run cannot exceed roughly a dozen
calls.
• Lab 0 prints token counts. Multiply by the per-token price on the pricing page to know your exact
spend.

export const MOCK = process.env.MOCK === "1";
export const MODEL_ID = process.env.OPENAI_MODEL ?? "gpt-4o-mini";
export type PlanStep =
  | { tool: string; input?: Record<string, unknown> }
  | { text: string };
function usage(input: number, output: number) {
  return {
    inputTokens: { total: input, noCache: input, cacheRead: 0, cacheWrite: 0 },
    outputTokens: { total: output, text: output, reasoning: 0 },
    raw: undefined,
  };
}
/** A fake model that replays a fixed plan: one step per model call. */
export function scriptedModel(plan: PlanStep[]): LanguageModel {
  let i = 0;
  return new MockLanguageModelV3({
    provider: "mock",
    modelId: "scripted",
    doGenerate: async () => {
      const step = plan[Math.min(i, plan.length - 1)]!;
      i++;
      if ("text" in step) {
        return {
          content: [{ type: "text", text: step.text }],
          finishReason: { unified: "stop", raw: undefined },
          usage: usage(0, 0),
          warnings: [],
        };
      }
      return {
        content: [{
          type: "tool-call",
          toolCallId: `mock-${i}`,
          toolName: step.tool,
          input: JSON.stringify(step.input ?? {}),
        }],
        finishReason: { unified: "tool-calls", raw: undefined },
        usage: usage(0, 0),
        warnings: [],
      };
    },
  }) as unknown as LanguageModel;
}
/** Real OpenAI model, or the scripted mock when MOCK=1. */
export function getModel(plan: PlanStep[]): LanguageModel {
  if (MOCK) return scriptedModel(plan);
  const key = process.env.OPENAI_API_KEY;
  if (!key) {
    console.error("OPENAI_API_KEY is not set. Export it, or run with MOCK=1 to rehearse.");
    process.exit(1);
  }
  return createOpenAI({ apiKey: key })(MODEL_ID);

}
export function banner(title: string) {
  console.log(`=== ${title} ===`);
  console.log(MOCK
    ? "mode: MOCK (scripted model, no network)"
    : `mode: REAL (OpenAI ${MODEL_ID})`);
  console.log("");
}
/** Print every step of a generateText result: tool calls, tool results, text. */
export function printSteps(result: { steps: any[]; text: string; usage?: any }) {
  console.log("\n--- Steps ---");
  result.steps.forEach((s, n) => {
    const parts: any[] = s.content ?? [];
    for (const p of parts) {
      if (p.type === "tool-call") {
        console.log(`${n + 1}. model called ${p.toolName}(${JSON.stringify(p.input)})`);
      } else if (p.type === "tool-result") {
        console.log(`   -> result: ${JSON.stringify(p.output).slice(0, 120)}`);
      } else if (p.type === "tool-error") {
        const msg = String(p.error?.message ?? p.error).slice(0, 140);
        console.log(`   -> ERROR returned to model: ${msg}`);
      } else if (p.type === "text" && p.text) {
        console.log(`   model said: ${p.text.slice(0, 200)}`);
      }
    }
  });
  console.log("\n--- Final answer ---");
  console.log(result.text || "(no text)");
  if (result.usage) {
    const u = result.usage;
    console.log(`\ntokens: input=${u.inputTokens ?? "?"} output=${u.outputTokens ?? "?"}`);
  }
}
/** Friendly explanation of common OpenAI errors. */
export function explainError(e: any) {
  const status = e?.statusCode;
  const msg = String(e?.message ?? e);
  console.error("\nERROR:", msg.slice(0, 300));
  if (status === 401) {
    console.error("=> The key is wrong or revoked. Check OPENAI_API_KEY.");
  } else if (status === 429) {
    console.error("=> Rate limit or no credit left (insufficient_quota). Check billing.");
  } else if (status === 404) {
    console.error(`=> Model '${MODEL_ID}' not found. Try OPENAI_MODEL=gpt-4o-mini.`);
  } else if (/ENOTFOUND|ECONNRESET|ETIMEDOUT|fetch failed/i.test(msg)) {
    console.error("=> Network. Set HTTPS_PROXY if your company uses a proxy.");
  }
}
