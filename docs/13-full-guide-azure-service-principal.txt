An API key is one secret that unlocks the door directly. A service principal is an identity: it proves who it is,
gets a short-lived token, and the resource checks a role (RBAC) before answering. The script does steps 1 to 3 by itself.
How one request reaches the model with a service principal. Steps 1 to 3 are done by two library calls.
1.2 Why companies prefer this over a key
• Nothing permanent travels. The token expires in about an hour. A leaked token is worth little; a
leaked key is worth a monthly bill.
• Least privilege. The principal gets exactly one role on exactly one resource: 'Cognitive Services
OpenAI User'. It cannot create resources or read other people's data.
• Audit and rotation. Every call is logged under the principal's name. Secrets have expiry dates and
can be rotated without touching code.
• No personal account on a managed device. This is the point your mentor is solving.

NOTE The deployment name is the number one source of confusion
In Azure you do not call a model, you call a deployment: a named copy of a model inside the resource, created
by an admin. The code sends that name in the 'model' field. If the admin called it 'chat-mini', then
AZURE_OPENAI_DEPLOYMENT=chat-mini, even though the model behind it is gpt-4o-mini.
LOOPHOLE Secret hygiene is stricter than with a personal key
The secret belongs to the company. Export it only in the Git Bash window (export
AZURE_CLIENT_SECRET=...), never in .bashrc, never in a file inside the repo, never in Copilot Chat, never in a
ticket. If it ever lands in a file, tell your mentor so it can be rotated. git status before every commit.

2.1 Why the repo itself needs no change
• The gate sees events, not models. createPetriflowGate(nets).wrapTools(tools)
intercepts each tool's execute function. It receives a tool name and input, consults the nets, and
allows or throws. The identity of the model that asked is not part of the event.
• The engine's decision provider is an interface. Lab 4 implements choose(req); what happens
inside (OpenAI, Azure, a coin flip) is invisible to the Scheduler.
• The repo's own examples are Anthropic-only. They build the model with
anthropic("claude-..."). They are not needed for the labs; Part 4.6 shows the optional two-line
swap if you ever want them on Azure.

WHY THIS DECISION Why environment variables and not a config file
Secrets must never be in files inside the repo. Env vars live in one shell window and vanish when it closes. It also
keeps the lab commands identical to the OpenAI guide: only the export lines differ.
3.2 The token flow

passed in realModel()
Two library calls do all the OAuth work. Nothing in PetriFlow knows a token exists.
Two calls from @azure/identity plus one option of createAzure replace all OAuth plumbing.
WHY THIS DECISION Why DefaultAzureCredential and not ClientSecretCredential
ClientSecretCredential works only with a secret. DefaultAzureCredential tries a chain: the same env vars (secret
or certificate), then cloud identities, then an existing az login. If your mentor hands you a certificate, or prefers
az login --service-principal, the code does not change. Cost: a slower first failure when nothing is
configured (it tries every link).

WHY THIS DECISION Why @ai-sdk/azure and not the 'openai' npm package already in the repo
The repo has the openai node SDK (used by one comparison script). Its AzureOpenAI client also accepts a
token provider, but it is not a Vercel AI SDK LanguageModel, so the gate's wrapTools and generateText could not
use it without an adapter. @ai-sdk/azure@3 is the provider that matches ai@6 and @ai-sdk/openai@3 already
installed, and it has a tokenProvider option that is invoked on every request.
3.3 One request on the wire
POST https://<resource>.openai.azure.com/openai/v1/chat/completions
Authorization: Bearer eyJ0eXAiOiJKV1QiLCJhbGciOi...   (no api-key header)
{ "model": "<AZURE_OPENAI_DEPLOYMENT>", "messages": [...], "tools": [...] }
'model' carries the DEPLOYMENT NAME. Sending 'gpt-4o-mini' when the admin named it 'chat-mini' gives 404 DeploymentNotFound.

3.4 Endpoint normalisation
Admins hand out endpoints in different shapes. azureBaseURL() turns the bare resource URL into the
v1 base the SDK expects, and leaves anything with a path alone so gateways keep working. Verified by
running it:
azureBaseURL() outputs
https://foo.openai.azure.com          -> https://foo.openai.azure.com/openai/v1
https://foo.openai.azure.com/         -> https://foo.openai.azure.com/openai/v1
https://foo.openai.azure.com/openai/v1 -> https://foo.openai.azure.com/openai/v1
https://gw.corp.example/apim/aoai     -> https://gw.corp.example/apim/aoai
NEEDS RESEARCH Things this guide could not verify without real credentials
(1) Whether your resource is a classic Azure OpenAI resource (*.openai.azure.com) or a Foundry project
endpoint (*.services.ai.azure.com); the token scope may differ for the latter, hence the
AZURE_OPENAI_SCOPE override. (2) Whether an API gateway in front needs an extra subscription header;
createAzure has a headers option for that. (3) Whether the newest @azure/identity honours
AZURE_TOKEN_CREDENTIALS to shorten the credential chain. Report what you see on the first real run.

export function banner(title: string) {

/** Print every step of a generateText result: tool calls, tool results, text. */
export function printSteps(result: { steps: any[]; text: string; usage?: any }) {
  console.log("\n--- Steps ---");
  result.steps.forEach((s, n) => {
    const parts: any[] = s.content ?? [];
    for (const p of parts) {
      if (p.type === "tool-call") {
        console.log(`${n + 1}. model called ${p.toolName}(${JSON.stringify(p.input)})`);
      } else if (p.type === "tool-result") {
        console.log(`   -> result: ${JSON.stringify(p.output).slice(0, 120)}`);
      } else if (p.type === "tool-error") {
        const msg = String(p.error?.message ?? p.error).slice(0, 140);
        console.log(`   -> ERROR returned to model: ${msg}`);
      } else if (p.type === "text" && p.text) {
        console.log(`   model said: ${p.text.slice(0, 200)}`);
      }
    }
  });
  console.log("\n--- Final answer ---");

  console.log(result.text || "(no text)");
  if (result.usage) {
    const u = result.usage;
    console.log(`\ntokens: input=${u.inputTokens ?? "?"} output=${u.outputTokens ?? "?"}`);
  }
}

    if (aad === "AADSTS700016") console.error("   AADSTS700016 = client id not found in that tenant.");

    return scriptedModel([
      { tool: "deploy", input: { version: "v1" } },
      { text: "Deploy attempted." },
